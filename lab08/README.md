## Выбор структуры данных

- **`dict` для частот и сумм.** Нужно соответствие «ключ → значение» и быстрый
  поиск/обновление по ключу. Список пар здесь неудобен: для добавления к счётчику
  пришлось бы каждый раз искать элемент. Словарь даёт обновление за один шаг
  `counts[word] = counts.get(word, 0) + 1`.
- **`set` для тем.** Нужны уникальные элементы и операции над множествами:
  пересечение `&` даёт общие темы, объединение `|` — все уникальные. У множества
  нет индексов и гарантированного порядка, поэтому перед выводом применяется
  `sorted()`, чтобы результат был воспроизводимым.
- **`dict` для записи занятия.** Запись имеет именованные поля (`title`, `hours`,
  `completed`) и значения, которые меняются. Именованные ключи делают код
  читаемым (`record["title"]` вместо позиции), а словарь, в отличие от кортежа,
  позволяет менять и добавлять поля. Кортеж здесь не подходит как изменяемая
  запись, но хорош как неизменяемая пара.
- **`tuple` для пары.** Пара `(title, hours)` не должна меняться, и кортеж
  защищает её от случайной правки; распаковка `title, hours = pair` даёт сразу
  две переменные.
- **`list` словарей для набора записей.** Нужен порядок (названия выдаются в
  исходном порядке) и повторяющиеся категории, что запрещено во множестве.

## Поведение `.get()`

`record.get("hours", 0)` и `counts.get(word, 0)` возвращают значение по ключу,
а если ключа нет — указанное запасное значение (`0`) вместо ошибки. Это позволяет
накапливать сумму или счётчик без предварительной проверки `if key in ...`:
`totals[category] = totals.get(category, 0) + record["amount"]` при первом
появлении категории берёт `0` и создаёт ключ, при последующих — прибавляет к
уже сохранённой сумме. Обычное обращение `record["hours"]` при отсутствии ключа
возбуждает `KeyError`, поэтому `.get()` удобен для необязательных полей и
счётчиков. Сортировка множества перед выводом нужна потому, что порядок
элементов множества не гарантирован и без `sorted()` результат был бы
нестабильным.
